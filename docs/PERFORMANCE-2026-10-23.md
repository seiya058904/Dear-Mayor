## 实际修改与取舍

1. **完整游戏字库的网页子集。** 原字体 5,305,668 bytes / 25,694 codepoints；新字体 542,856 bytes / 2,339 codepoints，减少 **89.77%**。扫描全部 `src/`，包含当前内容、目录机器/原稿快照、V1/V2/V3 冻结副本、动态日期和异常提示，另纳入 HTML、manifest、可打印 ASCII，并解码 Unicode 转义。源文件中 U+3400 是汉字检测正则边界，原字体也不支持；未新增字体回退。原字体、OFL、美术保持原字节。
2. **首屏比例在绘制前设置。** 全量子路径测试复现 1920×1080 先以 `--scene-scale:1` 测量，再变成 `1.1477151965993624`，造成同一次检查前后几何不一致。新测试在首个 DOM 提交的 MutationObserver 中捕获比例：修复前确定失败、修复后通过。只把已有缩放 effect 改为 `useLayoutEffect`；监听/清理、比例公式和响应式规则不变。不是给测试添加等待或扩大误差。

字体 preload 与 CSS 同时引用 `wenkai-game.woff2`，worker 缓存新字体并排除保留的原件；仍是 23 项完整运行资源，每项继续 SRI 校验。未改 worker 的等待激活、重试、scope 隔离或 HTTP 缓存复用机制。来源与重建方法见 [ASSETS.md](ASSETS.md)。[FontTools 子集文档](https://fonttools.readthedocs.io/en/latest/subset/index.html)用于确认布局特性、hinting 与 WOFF2 选项；[React 文档](https://react.dev/reference/react/useLayoutEffect)说明绘制前 effect 的语义。同步工作仅为两个 viewport 数值、一项比例和样式写入，没有新增同步历史回放。

## 瓶颈证据链

- `src/content/index.ts` 同步注册全部 1,160 文书；`catalog.ts` 的机器目录源文件 1,354,746 bytes，历史原稿 37,089 bytes；42 个冻结源文件共 628,077 bytes。它们参与同步恢复和旧 pending 解释，源码字节数不能直接当作独立压缩包大小。
- 基线/最终生产构建都转换 139 个模块；主 JS 约 2,832.34 kB，Vite gzip 约 1,102.94 kB，CSS 约 8.74/2.76 kB。最终 JS 仅增加首屏 hook 名称长度，没有内容拆分。大包警告保留。
- 首屏字体 preload 与主包共同占用网络。独立诊断样本复现桌面/移动慢网 FCP 40.58/40.51 秒、离线完整 90.35/90.27 秒。它们只用于诊断，不混入正式五轮统计。
- 画面按 `<picture>` 与媒体查询选用桌面/竖版纸张和背景。WebP 单项：宽背景 1,886,514；竖屏背景 1,739,326；桌面纸 1,163,606；竖版纸 1,290,128；便笺 1,312,942 bytes；四按钮各约 85–91 kB。初始页请求、优先级、图片选择与 worker 后续补全分别记录于原始请求日志。全部响应式资源仍完整离线缓存。
- 完整 decoded 缓存从 16,070,265 降至 11,307,474 bytes，均 23 项。字体原件继续可从站点访问，故部署目录总体大小不等于玩家传输量或离线占用。
- 现有长期恢复逐笔核验真实历史；现有 `verifiedRaw` 避免常规保存反复重放。此次未修改这些正确性边界。

未采用：拆分内容/冻结引擎（会改变同步恢复及离线 chunk 错误路径，当前收益优先级低于字体）；删除 preload（不能减少字体总量，可能推迟真实字形）；图片再压缩（现有无损 WebP，没有新增画质不变的收益证据）；提前 worker 下载（可能争抢首屏）；多标签同步系统与未复现的端口竞态（超出核心范围）。这些不是被宣称为已实现或已证明有效的优化。

**P3初始化时钟的不利结果也保留：** 正常移动DOM中位数73.9→82.5ms；桌面慢网单样本最大longtask的中位数127→141ms（基线121–130、最终125–145ms）。这一个长任务发生于文书DOM之前的模块初始化，不能声称CPU全面加速，也没有精确归因证据；真实操作与离线等待仍显著减少。其余正常网络无≥50ms longtask，移动慢网最大longtask中位数123→122ms。

**P3重复请求：** 最终正常移动5/5样本多传88,084–173,433 bytes的按钮图；基线桌面慢网1/5样本也多传88,084 bytes。日志表明window.load注册worker可早于React首个DOM，初装预取与页面资源加载竞争，HTTP缓存复用并非每次全命中。最终全部23项SRI/离线门禁仍通过；正常移动首次总传输依然减少32.6%，其他场景中位数减少33.2%。保留真实额外请求，不宣称零重复，未扩大修改worker安装协议。

同机 Windows、Node 24.15.0、固定 Playwright 1.64.1 / Chromium 156.0.8078.4；桌面 1672×941 DPR1，移动仿真 390×844 DPR2.75、触摸/移动布局。每个版本 × 设备 × 网络 **5 个独立冷 context**，共 40 样本，逐轮 AB/BA 交错；root 3 轮、子路径 2 轮，双方路径一致。生产 gzip HTTP 服务器和资源选择规则完全相同。性能采样双方均设减少动态效果，默认纸面动画另外由完整 E2E 覆盖；未将测试输入节奏当作玩家手速。

正常是未节流 localhost；慢网是共享名义 200,000 bytes/s、150ms 响应延迟、50ms FIFO 预算，覆盖页面和 worker，并配合 4×CPU。Windows 定时器降低实际吞吐，FIFO 不模拟公网 HTTP/2 多路优先级，因此数字是受控模型，不能宣传为真实公网或实体手机等待时间。

DOM 为首封及四个未禁用按钮出现；FCP 为 Paint Timing；可交互要求 FCP、字体 ready、纸张及四个按钮图片全部 decode，再经过两帧，执行真实指针批准且确实持久化第一笔决定。仍不是实体屏幕/手指延迟。离线为完整安装 ready，再确认 controller；字体为文书出现后的 fonts.ready。传输为服务器响应编码 body，不含 TCP/TLS；“操作时字节”是服务器到该检查点已写出的 body。浏览器资源时间/优先级、worker 请求、longtask、逐项缓存均留原始证据。

此前仅在 FCP 后执行 DOM click 的交错采样保留为 `performance-dom-diagnostic.json`，不混入正式统计。其瀑布图证明 FCP 时美术尚未完成（首轮慢网约62→32秒才收完首屏图），因此主动收严后重新完整采样，避免把文字出现冒称整幅画面已经能看见并操作。

重访与离线刷新均在已有完整缓存下测量，保留对应 1×/4×CPU，网络不再限速；重访计至文书可见且 fonts.ready，离线刷新计至文书可见，之后再验证离线换宽度并批示 C。小毫秒差异和极端值不作统计显著性结论；没有给 CI 加机器不稳定的绝对性能门槛。完整样本、中位数与 min/max 见 [PERFORMANCE-2026-10-23.json](PERFORMANCE-2026-10-23.json)。
